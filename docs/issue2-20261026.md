## 흰 선 원인 확정 및 수정

첨부 화면을 확대하니 선은 주로 띄어쓰기 직후에 나타났다. ISO에서 추출한 한글 글리프 자체의 바깥 테두리는 비어 있었다. 문제는 공백을 포함한 ASCII를 변환하는 실행파일 코드였다.

- `0x128B60`: 전각 글리프를 공용 24×24 버퍼에 쓴다.
- `0x128CA8`: 반각 ASCII의 16×24 픽셀만 쓰고, 각 행 오른쪽 8픽셀을 **지우지 않고 건너뛴다**.
- 따라서 전각 글리프 다음에 공백을 그리면 오른쪽에 앞 글자의 획이 남는다. 이 데이터가 폰트 아틀라스로 복사되어 경계에서 샘플링될 수 있다.
- 원본 MIPS 코드를 Unicorn에서 직접 실행해 `기 → 공백` 순서에서 오른쪽 **60픽셀**의 잔상이 남음을 재현했다. 원래 공백의 16×24 영역은 완전히 비어 있었다. 이는 빈 공백 글리프 파일에 획이 있다는 문제가 아니라 공유 변환 버퍼 초기화 누락이다.
- `0x128E20`, `0x128E24`의 NOP 두 개를 `sw zero,0(t2)`, `sw zero,4(t2)`로 바꿨다. 기존 2회 반복 루프에서 오른쪽 8칸을 모두 비운다. 크기·자간·팔레트·분기·줄바꿈은 바뀌지 않는다.
- 수정 후 `기 → 공백` 잔상 **0픽셀**, ASCII 96개 전체의 기존 16×24 픽셀·팔레트 동일, 오른쪽 8칸 0, 버퍼 앞뒤 canary 보존을 확인했다.

- 추가 전수검사: 빌드된 한글·자모 2,810개 각각에 대해 원본/수정 MIPS 전각 변환기를 실행했다. 24×24 전체 576픽셀이 원본 코드·수정 코드·글리프 데이터의 독립 기대값과 모두 동일했다. 앞 글자의 오른쪽 8칸을 자르는 수정이 아님을 확인했다. 기록: `build/issue2_full_width_verification.json`。
- 재현 검사: `python tools/verify_ascii_padding.py` (추가 검사 의존성: Unicorn). `tools/font_codec.py`에서 원본 명령 블록을 검증한 뒤 빌드에 반영한다. 최종 ISO의 실행파일 재읽기로 실제 삽입도 검사한다.

로컬 재현 비교: `build/issue2_space_scratch_proof.png` — 왼쪽은 앞서 그린 `기`, 가운데는 원본 코드가 만든 공백의 잔상, 오른쪽은 수정 후 공백이다.

앞서 업스케일링을 먼저 추정한 진단을 정정한다. PCSX2 어댑터 호환 문제로 실제 확대 화면에서 선이 사라지는지까지 확인한 것은 아니다. **버퍼 잔상 원인과 수정은 MIPS 코드 실행으로 검증했으며, PCSX2 화면 검증은 미실시**로 구분한다.

## 추가 확인이 필요한 항목

**일부 흰색 대사:** 화자·색상 계열 `mc` 명령 12,500개는 일본어 원본과 동일하다. 번역 빌드가 해당 명령을 누락한 증거는 없었다. 이슈 첨부의 재채기 묘사는 지문이므로 그 화면의 흰색만으로 색상 누락을 판정할 수 없다. 정확한 문제 문장을 확보한 뒤 원본 화자 지정과 비교해야 한다. 원본과 동일하다는 이유만으로 제보 전체가 정상이라고 단정하지 않는다.

## 줄바꿈 추가 수정

Windows판의 수동 개행을 가져온 상태에서 호칭 띄어쓰기만 수정해, `보/니`, `씨/의`처럼 어절·조사가 줄 사이에서 끊기는 문제를 놓쳤다. 두 제보 모두 수정 전 자료에도 해당 개행이 있었지만, PS2 반각 공백과 교정 후 폭에 맞춰 재배치하지 않은 것이 문제였다.

이번 교정 대상에서 단어·호칭 분리 및 추가 공백으로 늘어난 줄 폭을 조사해 504개 문장을 다시 배치했다. 41개는 일본어와 대조하며 표현을 다듬었다. 전각 24·ASCII 16의 기본 진행 폭과 보수적 전각 22칸(528) 기준으로 각 줄의 폭, 문장당 최대 3줄을 검사했다. 대화·지문 구분은 유지했다. 기존 줄 끝의 음절을 기계적으로 잘라 옮기지 않고 어절 단위로 배치했다. `사\n신`으로 쪼개져 남았던 `digi_05/tX/35`의 용어도 `악신`으로 바로잡았다.

- `main.scx/tX/81`: `그러고 보니`가 셋째 줄의 온전한 어구로 시작한다.
- `hina_06.scx/tX/163`: `히나기쿠 씨의`를 둘째 줄에 함께 놓고 셋째 줄은 `어머님은`으로 시작한다.
- 비교표의 `pre-wrap`을 `pre`로 바꿨다. 좁은 브라우저 패널에서 임의로 생기는 화면 줄바꿈을 없애고 실제 데이터의 LF만 보인다. 가로 스크롤을 지원하며 한국어 공백은 게임 인코딩과 동일하게 정규화해 비교한다.
- 상세 근거: `build/issue2_before_wrap.json`, `build/issue2_wrap_plan.json`. 비교표의 `줄바꿈 수정만` 필터로 확인할 수 있다.


## v0.4.1 후속 반영


Issue #2에서 요청했으나 v0.4에서 누락한 숫자 표기를 반영했습니다.

- 대사 676개에서 나이·기간·시간·인원·수량·횟수와 독립된 숫자 세기를 문맥에 맞게 아라비아 숫자로 변경했습니다. 예: 팔년 → 8년, 열살 → 10살, 두 사람 → 2명, 여섯시 → 6시.
- 선택지·장면 제목·시스템 문구·크레딧·개발용 중복 문구에도 같은 원칙을 적용했습니다. 원본 번역 입력의 다른 항목 73개를 수정했습니다.
- 이번·한층 더·서둘러·대답인 넷!처럼 숫자가 아닌 표현은 보존했습니다.

- v0.4의 맞춤법·악신·엔딩 번역·반각 문자 버퍼 잔상 수정도 포함합니다.

검증: 변경 대사 676개를 결과 ISO에서 다시 읽어 원본 번역 입력과 비교했습니다. 전체 빌드의 텍스트 왕복 검사, SCX 120개 구조·색상 명령 12,500개 보존 검사 및 ASCII 96개/전각 글리프 2,809개 픽셀 보존 검사를 통과했습니다. 배포 xdelta는 깨끗한 원본에 재적용하여 결과 ISO 해시 일치를 확인했습니다.

실제 PCSX2 플레이 화면 재검증은 하지 않았습니다. 일부 문구가 흰색으로 표시된다는 제보는 해당 문장·장면이 특정되지 않아 별도 미해결 상태입니다.

패치는 이전 패치본이 아닌 일본판 Premium-ban 원본 ISO에 적용해 주세요.
